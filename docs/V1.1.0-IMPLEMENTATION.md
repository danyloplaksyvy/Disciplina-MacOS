# Disciplina v1.1.0 — Goals & Progress

Version 1.1.0, build 5 extends v1.0.3. Weekly Review is deferred to v1.1.1.

## Behavior

Goals have a required title and success criterion, optional calendar target day, and Active/Achieved/Archived lifecycle. Achievement is explicit; archive restores the prior state. All states remain editable. Milestones are manually ordered and completed; zero milestones displays no percentage. Task completion never completes milestones or achieves a goal.

Tasks optionally link to one goal. A running task must pause before reassignment; resuming is manual. A new session snapshots its goal. Existing pre-upgrade sessions remain unassigned. Manual time uses the task goal when saved, even for backdated work. Editing a duration retains attribution; permanent session/task deletion removes its goal effort, while soft deletion retains it.

A recurring series stores its future goal. Changing the current occurrence updates future copies atomically; historical occurrences affect only themselves. Goal lifecycle does not stop recurrence or timing.

Task and milestone deletions share a chronological, session-local Undo stack. Native text Undo is unchanged. Permanent session deletion remains outside Undo.

## Architecture and data

One TaskStore owns committed task, session, recurrence, goal and milestone values. GoalService owns goal/milestone rules; GoalProgressService derives cached progress and effort. TimerCoordinator owns session attribution and goal reassignment guards. The existing repository commits the complete snapshot in one SwiftData transaction with rollback.

Schema V4 is frozen. V5 adds optional goal links, immutable session attribution, and Goal/Milestone records. Staged V1–V4 migration uses SQLite backups, isolated generations, preservation checks and atomic manifest publication. JSON format 4 includes all collections; formats 1–3 import without goal associations. Restore validates all references and goal totals before activation.

## UI

The main window starts at 1100 × 700 pt, limited by the screen. Native navigation offers Tasks, Goals and Settings; it collapses below 1000 pt with a compact destination menu. Existing 360/300 pt task/detail minimums and per-window selection/divider/day state remain. Goals show lifecycle sections, editable details, milestone progress, shared tasks, and attributed work. Global capture stays unassigned and the menu bar remains unchanged.

## Release gates

Local domain tests, Xcode persistence tests, light/dark UI regressions, clean ad-hoc arm64 packaging and source-commit verification are required. Record actual results in VALIDATION.md. Real login, macOS 14, physical sleep, multi-monitor/Spaces, VoiceOver, contrast, Reduce Motion and capture latency require device evidence; CI is not a substitute. Personal migration snapshots must remain local and uncommitted.
