# Disciplina 1.0.3 · build 4

## Behavior

- Application startup owns storage, shortcuts and one persistent status item. Main-window creation is explicit: normal launch, Dock reopening and Open Disciplina create/show the same window; login launch creates no main window. Storage failure remains accessible from the status item.
- Rows receive selection/focus state and use native selected foreground colors, including timer controls and the actions menu. Unselected actions retain burgundy.
- Main tasks appear under creation-day headers (Today, Yesterday, localized year-bearing dates), newest first. Nonempty status sections retain their previous ordering. Day collapse state lives with the main window. Calendar events, wake, activation and a one-shot next-midnight timer refresh grouping; presentation ticks do not.
- Repeat rules support daily, weekdays and selected weekdays. One unfinished occurrence remains current indefinitely. Completion/skip reserves one future ID for the next eligible calendar day; due checks materialize it atomically with actual creation time, original scheduled day and no sessions. Late returns never produce a backlog.
- Current completed occurrences can reopen and cancel the pending copy. Reopening older occurrences detaches them. Renaming changes the selected title and future series title. Skip, stop, schedule edits, completion and timer closure use the shared transaction boundary.
- Deletion Undo restores recurrence only when the series revision still matches the post-deletion revision. Otherwise it restores independently and explains why. Recently Deleted restoration always detaches recurrence. Permanent deletion clears obsolete current pointers while preserving pending successors.
- Settings manages active series even while a successor is pending. Stop retains history. No background launches, notifications, reminders or timer auto-starts.

## Data safety

Frozen schemas V1–V3 remain in the migration chain. V4 adds optional task series/date metadata and a persisted series record. Manifested V2/V3 stores and legacy V1 stores migrate through SQLite WAL-consistent snapshots and separate generations. Original records are compared before manifest activation. Restore also compares series after writing its replacement.

JSON format 3 includes recurrence. Formats 1/2 import as nonrecurring; IDs, task dates and sessions retain their previous meanings. Validation checks unique IDs, links, current-task state, reserved successor IDs, eligible dates, status consistency, duration overflow and session invariants before commit/activation.

Calendar dates are Gregorian year/month/day values. Scheduling uses calendar-day addition rather than 24-hour intervals. The date itself survives time-zone changes; materialization uses the current local day.

## Validation

Local and CI results are recorded in `VALIDATION.md`. Native real-login, macOS 14, multi-monitor and accessibility acceptance remain separate gates; simulated login and CI do not establish those results.
