# Disciplina v1.1.2 — Reliability & Task Search

Version 1.1.2, build 7. macOS 14 minimum, schema V6 and JSON format 5 unchanged.

Tasks provides native title search, status and goal filters. Matching is a trimmed, case/diacritic-insensitive literal substring; restrictions combine with AND. Deleted tasks are excluded. All goals, Unassigned, and lifecycle-grouped individual goals are available. Search never changes capture defaults, task dates, goal links or recurrence.

The pure TaskQuery projection preserves the shared store's day and status ordering, removes empty groups, and exposes result IDs/counts. The window caches its projection on query, committed day-group and availability changes; visual stopwatch ticks do not rebuild it. Unavailable state never presents stale counts as authoritative.

Query, filters, collapsed days, selection, details, divider position and inline title drafts live for the window session. Active filters temporarily expand day groups. Removing a row from results does not close its details or discard its draft. Restoring the row restores the draft. Whole-store replacement clears stale selection, drafts and filters. Task creation stays unassigned; hidden creations get a separate confirmation with Clear filters.

Command-F routes to Tasks/search only from the main window. Escape clears query text first, then returns focus to the list. Native field editors keep text Undo and consume typing; list completion/detail shortcuts do not intercept editable text. Search-result changes do not animate typing or restart timers.

PR #1 and #2 were integrated using merge commits. PR #2 was retargeted and revalidated against main before integration. Device checks and final build evidence are recorded in VALIDATION.md; unavailable checks are not implied by passing CI.

Debug UI runs with the existing 100-goal/10,000-task fixture can record search-input-to-result-draw-pass timings in the application's temporary directory, `Disciplina-search-latency.json`. The instrumentation is compiled out of Release, records only milliseconds (no queries/tasks), and is enabled only by both UI-test and fixture flags. This is a display-pass proxy, not a physical-screen latency measurement.
