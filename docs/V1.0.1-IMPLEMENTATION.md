# Disciplina 1.0.1

Implementation follows the approved October 20 PRD. Existing task IDs, dates, titles, preferences, and bundle identity are retained.

## Decisions

- Pause ends a session. Complete finishes the task. There is no separate Stop action.
- While running, the native menu bar displays a static burgundy dot, elapsed session time, and the existing checkmark. Idle/paused returns to the incomplete-task count.
- Deletion is soft, supports immediate Undo and native deletion Undo, and can be restored from Settings. Recorded sessions remain intact. Permanent deletion requires confirmation.
- Backup JSON format 1 uses UUID strings, millisecond Unix timestamps, and integer millisecond durations. Preferences are excluded.

## Data safety

V1's original store is never migrated or replaced. SQLite backup includes committed WAL data; SQLite may initialize its own WAL bookkeeping while opening the source, without changing task records. Migration runs on a separate generation; an atomic manifest selects a generation only after validation. Migration backups and previous generations are retained locally without automatic pruning.

Restore validates the whole document, pauses timing, snapshots the current store, creates a new generation, normalizes open sessions to interrupted, validates, then switches the manifest. Failure before publication leaves the original selected. Never manually delete database or WAL files to recover a failed launch.

## Timing

One main-actor coordinator owns active timing. SuspendingClock measures awake intervals; ContinuousClock detects abnormal gaps and missed suspension. Wall-clock dates do not determine duration. Checkpoints persist cumulative milliseconds every five seconds. Visual ticks do not save. Gaps over fifteen seconds or a continuous/awake divergence of at least one second discard untrusted time and pause conservatively. Failed checkpoints freeze timing until recovery.

The app never resumes a session across process restart. Open sessions close at their last committed checkpoint. Potential checkpoint loss is preferable to fabricated work duration.

## Validation

Run `bash scripts/test-core.sh` for deterministic domain/timer tests. Xcode CI covers SwiftData migration, WAL snapshots, atomic persistence, staged restore and UI regressions. UI tests use isolated memory stores.

The development binary supports `--verify-migration-copy <directory>` to validate a private COPY of a V1 store. Prepare that copy with SQLite's backup API; never point diagnostics at the live application directory. The command prints counts only and exits. Personal database copies must never enter Git or CI artifacts.

Release readiness remains pending until macOS 14/current-OS, appearance, VoiceOver, focus/Spaces/full-screen/multiple-monitor, sleep/wake, and performance checks are recorded. Automated results are recorded separately in VALIDATION.md.
